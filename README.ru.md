# [Swobu](https://swobu.com/) — маршрутизатор LLM и поставщик моделей для VS Code

Сохраните привычный процесс разработки. Выбирайте модели, которые за ним работают.

Используйте маршрут Swobu как нативную модель VS Code или подключайте Claude Code и Codex, сохраняя официальные интерфейсы. Настройте поставщиков и резервные варианты в Swobu один раз: выбранный маршрут остаётся прежним при смене модели.

Установите расширение из [Visual Studio Marketplace](https://marketplace.visualstudio.com/items?itemName=swobu.swobu) или найдите `swobu.swobu` в VS Code. Один платформонезависимый пакет поддерживает локальные хосты расширений, WSL, Remote SSH и контейнеры разработки.

## Модели в VS Code

Откройте **Manage Language Models**, выберите **Swobu**, затем маршрут. Swobu управляет выбором поставщика и резервированием. Вызовы инструментов для VS Code Agent включены по умолчанию.

## Claude Code и Codex

Выполните **Swobu: Connect Claude Code** или **Swobu: Connect Codex**, выберите рабочее пространство и продолжайте в официальном интерфейсе клиента. Существующая команда Swobu отвечает за конфигурацию и безопасную замену.

## Зачем маршруты?

Переключатель поставщиков меняет модель в редакторе. Маршрут позволяет менять доступные модели и настраивать резервирование за одним выбором модели. Сохраните клиент, а решение о поставщике передайте Swobu.

## Начало работы

1. Откройте **Swobu: Set Up** и настройте доступ к моделям.
2. Создайте маршрут для своих задач.
3. Выберите его в **Manage Language Models** и попросите Agent прочитать файл.
4. Откройте **Swobu: Open**, чтобы посмотреть результаты маршрутизации.

## Настройки модели

В **Swobu: Configure Model** выберите маршрут. Для изображений и инструментов доступны **Default**, **On**, **Off**. Для контекста и вывода — готовые значения и собственное положительное целое число. **Reset overrides** сразу восстанавливает значения по умолчанию без перезапуска.

По умолчанию: инструменты включены, изображения выключены, 32 768 входных и 4 096 выходных токенов. Это задаваемые вами возможности клиента, а не автоматически определённые свойства модели. Включайте изображения только для маршрута с подходящей моделью.

## Поставщики и работа системы

Настройте модели в Swobu, включая OpenRouter, Ollama, Bedrock, Azure и OpenAI-совместимые конечные точки. Учётные данные остаются в Swobu. VS Code направляет запросы локальному процессу Swobu, который отвечает за подключения, повторные попытки, резервирование и учёт использования. Расширение представляет маршруты как модели и передаёт поток ответа.

## Приватность и безопасность

Запросы, ответы и содержимое инструментов временно находятся в памяти расширения. Оно не сохраняет и не журналирует их и не имеет отдельного отправителя телеметрии. Для Swobu действуют собственные настройки приватности. См. [PRIVACY.md](PRIVACY.md) и [SECURITY.md](SECURITY.md).

## Удалённая работа, WSL и контейнеры

Расширение работает на хосте рабочего пространства; loopback-адрес относится именно к нему. Для удалённого пространства настройте Swobu на удалённой стороне. Квалификация пакетов и проверка установки обязательны до релиза.

## Помощь

После изменения маршрутов выполните **Swobu: Refresh Models**. Если Swobu недоступен, проверьте машинную настройку адреса. Перед разрешением замены конфигурации прочитайте вывод команды подключения.

[Сообщите об ошибке](https://github.com/swobuforge/swobu-vscode/issues), указав версию VS Code, платформу и текст ошибки. Не прикладывайте учётные данные или приватные запросы.

## Разработка и лицензия

Node 22, VS Code 1.135 или новее: `npm ci`, `npm test`, `npm run build`, `npm run package`. При наличии совместимой обычной установки Swobu также выполните `npm run test:integration`; на Linux без дисплея используйте `xvfb-run -a`.
