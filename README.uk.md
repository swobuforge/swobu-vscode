# [Swobu](https://swobu.com/) — маршрутизатор LLM і постачальник моделей для VS Code

Зберігайте звичний процес розробки. Обирайте моделі, що працюють за ним.

Використовуйте маршрут Swobu як нативну модель VS Code або підключайте Claude Code та Codex, зберігаючи їхні офіційні інтерфейси. Налаштуйте постачальників і резервні варіанти у Swobu один раз: вибраний маршрут залишається тим самим, навіть коли модель під ним змінюється.

Установіть розширення з [Visual Studio Marketplace](https://marketplace.visualstudio.com/items?itemName=swobu.swobu) або знайдіть `swobu.swobu` у VS Code. Один платформонезалежний пакет підтримує локальні хости розширень, WSL, Remote SSH і контейнери розробки.

## Моделі у VS Code

Відкрийте **Manage Language Models**, виберіть **Swobu**, а потім маршрут. Swobu керує вибором постачальника та резервуванням. Виклики інструментів для VS Code Agent типово ввімкнено.

## Claude Code та Codex

Виконайте **Swobu: Connect Claude Code** або **Swobu: Connect Codex**, виберіть робочий простір і продовжуйте в офіційному інтерфейсі клієнта. Наявна команда підключення Swobu відповідає за конфігурацію та безпечну заміну.

## Навіщо маршрути?

Перемикач постачальників змінює модель у редакторі. Маршрут дозволяє змінювати модельні ресурси й налаштовувати резервування за одним вибором моделі. Зберігайте клієнт, а вибір постачальника передавайте Swobu.

## Початок роботи

1. Відкрийте **Swobu: Set Up** і налаштуйте доступ до моделей.
2. Створіть маршрут для своїх завдань.
3. Виберіть його в **Manage Language Models** і попросіть Agent прочитати файл.
4. Відкрийте **Swobu: Open**, щоб переглянути результати маршрутизації.

## Налаштування моделі

У **Swobu: Configure Model** виберіть маршрут. Для зображень і викликів інструментів доступні **Default**, **On**, **Off**. Для контексту й виводу — готові значення та власне додатне ціле число. **Reset overrides** відразу відновлює типові значення без перезапуску.

Типово: інструменти ввімкнено, зображення вимкнено, 32 768 вхідних і 4 096 вихідних токенів. Це керовані вами заявлені можливості клієнта, а не автоматично визначені властивості моделі. Увімкніть зображення лише для маршруту з відповідною моделлю.

## Постачальники та робота системи

Налаштовуйте доступні моделі у Swobu, зокрема OpenRouter, Ollama, Bedrock, Azure та OpenAI-сумісні кінцеві точки. Облікові дані залишаються у Swobu. VS Code надсилає запити локальному процесу Swobu, який відповідає за підключення, повторні спроби, резервування та облік використання. Розширення відображає маршрути як моделі й передає потік відповіді.

## Приватність і безпека

Запити, відповіді та вміст інструментів тимчасово перебувають у пам’яті розширення. Воно не зберігає й не журналює цей вміст та не має окремого відправника телеметрії. Для Swobu діють його власні налаштування приватності. Див. [PRIVACY.md](PRIVACY.md) і [SECURITY.md](SECURITY.md).

## Віддалена робота, WSL і контейнери

Розширення працює на хості робочого простору; loopback-адреса стосується саме цього хоста. Для віддаленого простору налаштуйте Swobu на віддаленій стороні. Кваліфікація пакетів і перевірка встановлення є передумовами релізу.

## Допомога

Після зміни маршрутів виконайте **Swobu: Refresh Models**. Якщо Swobu недоступний, перевірте машинну адресу кінцевої точки. Перед дозволом заміни конфігурації перегляньте вивід команди підключення.

[Повідомте про помилку](https://github.com/swobuforge/swobu-vscode/issues), указавши версію VS Code, платформу та повідомлення про помилку. Не додавайте облікові дані чи приватні запити.

## Розробка та ліцензія

Node 22, VS Code 1.135 або новіший: `npm ci`, `npm test`, `npm run build`, `npm run package`. За наявності сумісної звичайної інсталяції Swobu також виконайте `npm run test:integration`; у Linux без дисплея використовуйте `xvfb-run -a`.
